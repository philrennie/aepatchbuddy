PB Patch Bay Module Editor — Guide
← Back to editor

The Module Editor is a visual tool for defining AE Modular module panels — placing jacks, knobs, switches, sliders, and labels, then exporting a module.json that Patch Bay understands. You can use it to document modules for your own patches, or to contribute new modules to the shared library.

Layout

The editor is split into three columns:

  • Left panel — module settings (name, ID, width, metadata) and tool selection.
  • Centre canvas — the live panel preview. Click in add-tool mode to place components; click in select mode to select and drag them.
  • Right panel — properties for the currently selected component (label, position, orientation).

The bottom bar has export and import actions.

Panel settings

  • Name — the human-readable module name shown in Patch Bay's sidebar and on the panel itself.
  • ID — a short, lowercase, hyphenated identifier (e.g. vco, ms-filter). This becomes the folder name and the JSON filename. It auto-derives from the name but can be edited independently. Must be unique within the library.
  • Width — panel width in Rack Units (1 RU = 160 px, ≈ 25 mm at AE Modular scale). Standard AE modules are 1–4 RU wide.
  • Custom SVG artwork — tick this if you are providing your own hand-drawn or vector panel artwork. Exports customImage: true in the JSON and expects a matching module.svg in the same PR folder. Leave unticked to let Patch Bay render the panel from the JSON automatically.
  • Manufacturer, Product URL, Documentation URL — optional; shown in the sidebar and as link buttons on rack instances in the patch editor.

Tools

Select a tool from the left panel (or use the keyboard shortcut), then click anywhere on the canvas to place a component. The editor switches back to Select automatically after each placement.

Grid & snap

The Snap checkbox in the left panel snaps placed and dragged components to a grid. The default is 10 px, which aligns well with AE Modular's nominal jack spacing. Disable snap for freeform positioning or set a smaller step (e.g. 5 px) for tighter adjustments.

The dotted background is the same 24 px decorative grid used in the patch editor — it is not the snap grid.

Component properties

Click a component on the canvas to select it. Its properties appear in the right panel.

  • Label / Connection name — the text shown next to the component on the panel. For jacks, this is also the name shown in Patch Bay's hover tooltips. Labels can be plain text or a waveform glyph — switch to the ∿ tab and pick a shape (sine, square, triangle, sawtooth or a combination).
  • Label position — jacks, knobs, and sliders have a 3×3 grid picker (above / below / left / right). Jacks at the panel edges conventionally use the inward direction.
  • Orientation (switches and sliders) — vertical or horizontal body; for a slider this is also the travel axis.
  • Length (sliders only) — travel length in native panel pixels (default 80). Snaps to the grid step while dragging the field.
  • Quick labels — one-click presets for common signal names: IN, OUT, MULT, THRU, B.GATE, B.CV, B.START, B.STOP. Click any to set the label instantly.
  • X / Y — exact pixel position in native panel space (before any app scaling). Edit directly for precise placement.
  • ID — read-only. Jacks use this ID to identify cable connections in saved patches; do not delete and recreate a jack if patches are already referencing it.
Deleting a jack that patches already reference breaks those cable connections. The editor warns you when deleting a component whose ID came from an imported module.json — the same caution applies if you re-export an edited module and distribute it.

Exporting

  • Copy JSON entry — copies the complete module.json object to the clipboard. Paste it into your favourite editor to review or tweak before saving.
  • Download JSON — saves {id}.json directly. This is the file to put in your PR. You will need to rename it to module.json once it is in the module subfolder
  • Download SVG — exports a {id}.svg panel image rendered from the same data. Useful as a reference or as the module.svg for a customImage: true. You will need to rename it to module.svg once it is in the module subfolder module. Only include it in the PR if Custom SVG artwork is ticked.

The editor auto-saves to browser storage as you work. Clearing the module or closing the tab does not lose your progress unless you explicitly click Clear module.

Importing

Click Import JSON to load an existing module.json back into the editor. This lets you reopen a module for editing without needing its original module.svg — all jack, knob, switch, slider, and label components are reconstructed from the JSON alone. Component IDs are preserved verbatim so a re-export won't break existing patch references.

Submitting a module to the library

The Patch Bay module library lives in the GitHub repository at github.com/philrennie/aepatchbuddy. To add a new module, open a pull request against the main branch:

  1. Fork the repository on GitHub (Fork button, top-right of the repo page).
  2. In your fork, create the folder src/modules/{your-module-id}/. The folder name must exactly match the ID field in the editor.
  3. Save your exported module.json into that folder.
  4. If you ticked Custom SVG artwork, also place your module.svg in the same folder. Otherwise, no SVG is needed — Patch Bay renders the panel from the JSON automatically.
  5. Commit your changes and open a pull request against philrennie/aepatchbuddy's main branch.
Validation runs automatically. A GitHub Actions lint workflow checks every PR that touches src/modules/**. It verifies the JSON schema, checks that a module.svg exists when customImage: true, and warns on malformed waveform tokens. The check must pass before the PR can be merged.

What happens on merge

When the PR is merged into main, a publish workflow automatically rebuilds data/modules.json from all individual module files and deploys the site to GitHub Pages. Your module appears in Patch Bay's library within a minute or two of merge.

Module guidelines

  • Use the real module name and manufacturer as they appear on the hardware or the manufacturer's website.
  • Jack names should match the panel silkscreen exactly where possible (e.g. 1V/OCT, GATE, OUT).
  • Do not include copyrighted panel artwork in module.svg — the auto-generated panel (no customImage) is always acceptable and preferred unless you have original artwork.
  • Only add a url or documentation field if you have a real, stable link to a product or documentation page.
  • One module per PR is strongly preferred; it keeps review and CI feedback clean.
