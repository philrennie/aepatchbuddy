# Contributing

Thanks for wanting to help build this out — patch-planning tools are way better when a whole community's modules are in them. A few ground rules before you dive in.

## 1. Don't be a dick

- Be respectful. Disagree about code, not about people.
- No harassment, personal attacks, or gatekeeping newcomers for asking "obvious" questions.
- Assume good faith. Most bad PRs are enthusiasm, not malice — help people fix it up rather than just closing it.
- Maintainers can and will remove comments, close threads, or block repeat offenders. This isn't a courtroom — "technically I didn't break a rule" isn't a defense if you're making the space worse for people.

That's really it. Full code of conduct energy, minimal word count.

## 2. No copyrighted material

This project represents real modules functionally — jack positions, knobs, switches, controls — **without** using manufacturer artwork, logos, panel photos, or other copyrighted visual assets.

When contributing a module definition or graphic:

- ✅ Describe the panel's *function* (what controls exist and where they sit relative to each other) in our own original visual style.
- ✅ Use the module's real name, in plain text, to identify it — that's descriptive/nominative use, not a reproduction of anyone's branding.
- ❌ Don't trace, crop, or copy panel graphics, fonts, or logos from manuals, datasheets, or product photos.
- ❌ Don't lift code, assets, or text from other projects unless it's under a license compatible with this one and you credit it properly.

If you're not sure whether something crosses the line, ask in your PR description before we merge it — much easier to sort out before than after.

## How to contribute

1. Fork the repo and create a branch for your change.
2. Keep PRs focused — one module/feature/fix per PR is easier to review than a grab-bag.
3. If you're adding a module definition, include the module name, manufacturer, and a short note on where you sourced the control layout (manual, own hardware, etc.) so it's easy to verify against copyrighted material.
4. Open the PR — the template will ask you to confirm the above.

Questions or unsure about any of this? Open an issue or start a discussion before you put the work in — happy to talk it through.
